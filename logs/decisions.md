# 判断ログ

議論で到達した判断と、その理由・却下した代替案の台帳。
同じ論点を後で蒸し返さないために残す。新しいものほど上にある。

ここに書くのは**ユーザーと合意した判断**（方針・スコープ・生活の前提・複数案から選んだ設計）。
Claude が実装中に選んだ技術的な選択とハマりどころは `KNOWLEDGE.md`。やることは `TODO.md`。
追記は `/decide`。新しいエントリは下の `---` の直後に入れる（`/decide` がそうする）。

1 エントリの形式（`/decide` と同じ。1 エントリ 1 判断）：

```
## YYYY-MM-DD <論点を一言で>

**論点**: 何を決めようとしていたか
**結論**: どう決めたか
**理由**: なぜその結論にしたか
**却下した代替案**: 検討して捨てた選択肢と、捨てた理由（なければ「なし」）
**確信度**: 高 / 中 / 低
**見直す条件**: この前提が崩れたら判断をやり直す、という条件（なければ「なし」）
```

## 2026-09-29 Web 原文と固定の保持文がぶつかる箇所の扱い

**論点**: Web で集めたプリセットの原文に、毎回入れる保持文（服装・構図を変えない）と矛盾する指示がある。
例として、フォトブースの原文は「新年の衣装に着替えさせる」、手描きアニメ映画風の原文は「背景を緑の丘に差し替える」と書いてあり、
手描きアニメ映画風の原文には実在のスタジオ名も入っている。原文のまま入れるか、書き換えるか、見送るか
**結論**: ユーザーが選択肢から「矛盾する箇所だけ書き換える」を選んだ。選択肢の中身は、服装を変える一文・背景を差し替える一文を外し、
スタジオ名を一般的な言い方に置き換える。書き換えた箇所は出典と並べて記録する。
ユーザー提供の 2 本（`diorama` `editorial-poster`、`docs/seed-prompts.md`）の原文には手を付けない
**理由**: 選択肢に添えた Claude の説明：矛盾したまま渡すと、どちらの指示が勝つかは AI 次第で結果が安定しない。
Claude の補足：CC BY 4.0 は改変を認めるが「変更したことを示す」ことを求めるので、出典と並べた記録がその表示を兼ねる
**却下した代替案**: 原文のまま入れる（結果が安定しない）／ぶつかる 2 本を見送る（ユーザーが選ばなかった）
**確信度**: 高
**見直す条件**: 書き換えた版で仕上がりが明らかに崩れたとき。
利用条件の明記が無い出典は改変してよいかも分からないので、そうした原文を採るときは改めて確認する。
適用範囲（Claude の推定）：プリセットの顔ぶれを選び直して別の Web 原文を採る場合も同じ扱いにする。違う扱いが要る原文が出てきたら確認する

## 2026-09-29 「条件」の再編（保持を固定化し、仕上がりの調整だけを選ばせる）

**論点**: 依頼の原文にあった「人物（顔・服装・ポーズ・家族構成を保持）」「背景・構図」のトグルを画面に残すか、プリセットが固定で持つか
**結論**: ユーザーが SPEC.md の案を「案のまま OK」とした。顔・服装・ポーズ・人数を変えない指示は画面のスイッチにせず、プロンプトに毎回自動で入れる。
画面で選ぶのは仕上がりの調整だけで、選択 3 つ（スタイル強度・色味・縦横比）と ON/OFF 6 つ
（文字なし・写っていない物を足さない・1 枚ずつ出力・柔らかい光・紙の質感・高精細）
**理由**: SPEC.md「保持は固定」の説明：OFF は「変えろ」ではなく「何も指示しない」だが、AI はスタイルを変えるときに指示が無いと顔立ちや人数を平気で変えるので、
常に入れておくのが安全で ON/OFF させる意味がない。`high-realism` と `strong-style` は同じ軸の両端なので 1 つのラジオにまとめる
**却下した代替案**: 保持も ON/OFF のスイッチにする（元の依頼どおり。ユーザーが選ばなかった）
**確信度**: 高
**見直す条件**: Qiita の実験で、保持文を常に入れると仕上がりが崩れるスタイルが見つかったとき（保持を外す実験モードは MVP 後に付ける）

## 2026-09-07 Qiita の実験に使う写真

**論点**: Qiita 記事の実験（どのプロンプト制約が効くか）に、子どもの実写真を使うか、後ろ姿・遠景・自分の写真で代用するか
**結論**: 子どもの写真を使う。ただし顔は分からないようにする。実験そのものは元の写真で行い、**記事に載せるときに入力・出力の両方の顔をモザイクで隠す**
**理由**: アプリのテーマが「子どもの写真を素敵に加工して思い出に残す」なので、代用写真では実験が題材とずれる。
顔を隠す手段として「プロンプトで顔を変える」案もあったが、それでは「顔を保持する指示が効くか」という実験自体が成り立たない。
入力にモザイクを掛けてから AI に渡す案も、AI がモザイクを見て結果が変わるので不可。掲載時の加工が唯一、実験を壊さない
**却下した代替案**: 後ろ姿・遠景・自分の写真で代用（題材とずれる）／プロンプトで顔を別人にする（保持の実験が成立しない）／入力写真にモザイクを掛けてから渡す（結果が変わる）
**確信度**: 高（2026-09-07 時点では Claude の推奨で「中」。2026-09-29 にユーザーが選択肢から「掲載時にモザイク」を選んで確定した）
**見直す条件**: モザイクで隠しても記事として伝わらない（仕上がりの良さが顔に依存する）と分かったとき

## 2026-09-07 プリセットの英文の出どころ

**論点**: プリセット 8 本のうち、Claude が下書きした 6 本の英文をそのまま使うか
**結論**: `diorama` と `editorial-poster` は検証済みなので確定。残りは **Web で公開されている実績のあるプロンプトを集めて種にする**。見つからないテーマだけ自作する。テーマ 7 本（依頼の原文）も仮であり、収集結果を見て入れ替えてよい
**理由**: Claude の下書きは効くかどうか未検証。他人が結果を出して公開しているプロンプトのほうが出発点として信頼できる。
外部由来のデータなので、`docs/seed-prompts.md` に出典 URL と確認日を併記する（`../CLAUDE.md`「コーディング規則」のマスタデータの扱いと同じ）
**却下した代替案**: Claude の下書き 6 本をそのまま採用して Qiita の実験で磨く（出発点の品質が担保できない）
**確信度**: 高
**見直す条件**: 集めたプロンプトの利用条件に再配布不可のものがあれば、その分は自作に切り替える
