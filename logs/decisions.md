# 判断ログ

議論で到達した判断と、その理由・却下した代替案の台帳。
同じ論点を後で蒸し返さないために残す。新しいものほど上にある。

ここに書くのは**ユーザーと合意した判断**（方針・スコープ・生活の前提・複数案から選んだ設計）。
Claude が実装中に選んだ技術的な選択とハマりどころは `KNOWLEDGE.md`。やることは `TODO.md`。
追記は `/decide`。新しいエントリは下の `---` の直後に入れる（`/decide` がそうする）。

1 エントリの形式（`/decide` と同じ。1 エントリ 1 判断）：

```
## YYYY-MM-DD <論点を一言で>

**論点**: 何を決めようとしていたか
**結論**: どう決めたか
**理由**: なぜその結論にしたか
**却下した代替案**: 検討して捨てた選択肢と、捨てた理由（なければ「なし」）
**確信度**: 高 / 中 / 低
**見直す条件**: この前提が崩れたら判断をやり直す、という条件（なければ「なし」）
```

## 2026-09-07 Qiita の実験に使う写真

**論点**: Qiita 記事の実験（どのプロンプト制約が効くか）に、子どもの実写真を使うか、後ろ姿・遠景・自分の写真で代用するか
**結論**: 子どもの写真を使う。ただし顔は分からないようにする。実験そのものは元の写真で行い、**記事に載せるときに入力・出力の両方の顔をモザイクで隠す**
**理由**: アプリのテーマが「子どもの写真を素敵に加工して思い出に残す」なので、代用写真では実験が題材とずれる。
顔を隠す手段として「プロンプトで顔を変える」案もあったが、それでは「顔を保持する指示が効くか」という実験自体が成り立たない。
入力にモザイクを掛けてから AI に渡す案も、AI がモザイクを見て結果が変わるので不可。掲載時の加工が唯一、実験を壊さない
**却下した代替案**: 後ろ姿・遠景・自分の写真で代用（題材とずれる）／プロンプトで顔を別人にする（保持の実験が成立しない）／入力写真にモザイクを掛けてから渡す（結果が変わる）
**確信度**: 中（「掲載時にモザイク」は Claude の推奨。ユーザーが「プロンプトで変える」を選ぶ可能性は残る）
**見直す条件**: モザイクで隠しても記事として伝わらない（仕上がりの良さが顔に依存する）と分かったとき

## 2026-09-07 プリセットの英文の出どころ

**論点**: プリセット 8 本のうち、Claude が下書きした 6 本の英文をそのまま使うか
**結論**: `diorama` と `editorial-poster` は検証済みなので確定。残りは **Web で公開されている実績のあるプロンプトを集めて種にする**。見つからないテーマだけ自作する。テーマ 7 本（依頼の原文）も仮であり、収集結果を見て入れ替えてよい
**理由**: Claude の下書きは効くかどうか未検証。他人が結果を出して公開しているプロンプトのほうが出発点として信頼できる。
外部由来のデータなので、`docs/seed-prompts.md` に出典 URL と確認日を併記する（`../CLAUDE.md`「コーディング規則」のマスタデータの扱いと同じ）
**却下した代替案**: Claude の下書き 6 本をそのまま採用して Qiita の実験で磨く（出発点の品質が担保できない）
**確信度**: 高
**見直す条件**: 集めたプロンプトの利用条件に再配布不可のものがあれば、その分は自作に切り替える
